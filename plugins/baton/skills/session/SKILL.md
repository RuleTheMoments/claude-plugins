# 프로젝트 세션 핸드오프

**레지스트리**: `~/.claude/handoffs/projects.json` — 프로젝트 이름 → 작업 디렉터리 + 핸드오프 문서 경로.
**상세 핸드오프**: 각 프로젝트 안(`workdir/handoff_doc`). 코드와 함께 버전 관리된다. 레지스트리는 그것을 찾아가는 색인일 뿐이다.
**도우미**: 아래에서 `H`는 `python3 -I "${CLAUDE_SKILL_DIR}/../../scripts/handoff.py"`를 뜻한다.

| `H` 명령 | 하는 일 |
|---|---|
| `H list` | 등록된 프로젝트를 **Claude 실행 폴더 기준**으로 나눈다 — ● 이 폴더에서 이어받기·갱신 / ◐ 작업 폴더 안 / ○ 다른 폴더. 레지스트리 점검(⚠)도 |
| `H resolve [이름]` | 이름·별칭으로, 이름이 없으면 실행 폴더로 프로젝트 하나를 고른다(JSON) |
| `H current` | 현재 세션 ID·이름·실행 폴더·트랜스크립트 폴더 |
| `H title <키>` | 현재 세션 이름을 `<키>`로. 다음 입력 때 훅이 적용한다 |
| `H stamp <키>` | 엔트리의 `updated`·`last_session_id`·`transcript_dir`를 현재 세션으로 |

**실행 폴더**는 claude를 띄운 폴더다. 세션 트랜스크립트는 `~/.claude/projects/<실행 폴더를 -로 바꾼 이름>/`에 쌓이고, `claude --resume <id>`는 같은 폴더에서 띄웠을 때만 그 세션을 찾는다. 그래서 목록은 이 기준으로 나눈다.

모드는 사용자의 말에서 정한다.

| 사용자가 | 모드 |
|---|---|
| "…불러와서 이어서 작업", "이어서 작업할 준비", "핸드오프 읽어줘", "resume" | **§1 이어받기** |
| "핸드오프 갱신", "지금까지 한 것 정리해서 남겨줘", `save` | **§2 갱신** |
| "…를 등록해줘", `register`, 레지스트리에 없는 프로젝트 | **§3 등록** |
| "핸드오프 목록", "이어받을 수 있는 거", `list` | **§4 목록** |

---

## §0 프로젝트 찾기 (모든 모드 공통)

1. 이름을 말했으면 `H resolve <이름>`. 키와 `aliases`를 대소문자 무시하고 대조한다.
2. 이름을 말하지 않았으면 `H resolve` — 실행 폴더 기준으로 고른다. `match`가 있으면 그것을 쓰고 "실행 폴더 기준으로 `<키>`를 골랐다"고 한 줄 알린다.
3. `match`가 없으면 — `H list` 출력을 보여주고 묻는다. `candidates`가 2–4개면 그 중에서 고르게 하고, 하나도 없으면 지금 이 프로젝트를 등록할지 묻는다(§3). 추측해서 아무 프로젝트를 열지 마라.

---

## §1 이어받기

### 0. 세션 이름을 붙인다

이번 턴에 훅 메시지 `[baton] 이 세션 이름을 '<키>'(으)로 붙였다 (세션 <ID 앞 8자>).`가 있고 `<키>`가 고른 프로젝트와 같으면 이미 됐다 — 그 이름과 ID를 보고 첫 줄에 쓴다. 아니면 `H title <키>`를 실행한다 — 이름은 사용자의 다음 입력 때 붙는다. 출력 줄(`세션 이름: …`)을 보고 첫 줄에 쓴다.

### 1. 읽는다

먼저 레지스트리 엔트리의 `one_line`, `warnings`, `last_session_id`를 본다. 그 다음 `workdir/handoff_doc`을 읽는다.

핸드오프 문서에 위험·다음 작업·함정 절이 있으면 **그 순서로** 읽는다. 함정 목록에 적힌 것은 **다시 확인하지 말고 믿는다** — 이전 세션이 실제로 밟아본 것들이다.

나머지 문서는 필요해질 때 읽어라. 미리 다 읽지 마라.

### 2. 문서를 믿지 말고 살아있는 상태를 확인한다

핸드오프는 마지막 갱신 시점의 주장이다. 실제와 갈릴 수 있다.

```sh
cd <workdir>
```

레지스트리의 `setup[]`을 실행해 환경을 복원하고, `verify[]`를 실행해 상태를 확인한다. 오래 걸리는 것(빌드, 설치)은 백그라운드로 돌려라.

`git status --short --branch`는 항상 본다 — 커밋 상태와 미추적 파일은 가장 흔한 드리프트 원인이다.

### 3. 어긋난 것을 보고한다

문서·레지스트리의 주장과 실제가 다르면 **고치기 전에 사용자에게 먼저 말한다.** 예: 테스트 수 불일치, 커밋 상태 변화, 서비스·클러스터 소실, 런타임 디렉터리 삭제, `H list`의 ⚠ 점검(트랜스크립트 없음, `transcript_dir` 불일치).

### 4. 짧게 보고하고 다음 행동을 제안한다

전체를 다시 설명하지 마라. 이 형태로:

- **세션** — `<이름> · <세션 ID 앞 8자>` (§1-0의 출력. 대기 중이면 "다음 입력 때 적용"을 붙인다)
- **어디까지 됐나** — 한두 문장
- **환경 상태** — `verify[]` 결과. 복원한 게 있으면 그것
- **어긋난 것** — 있으면. 없으면 이 줄을 생략
- **다음 작업** — 핸드오프의 우선순위 1번과 그것이 무엇을 막고 있는지
- **질문 하나** — 그 작업을 시작할지, 아니면 다른 것을 할지

레지스트리 `warnings`에 커밋되지 않은 상태가 적혀 있고 실제로도 그렇다면, **커밋할지 물어라.** 승인 없이 커밋하지 않는다.

## §2 갱신 (`save`)

`workdir/handoff_doc`을 다시 쓰고, 레지스트리 엔트리를 갱신한다.

### 먼저 사실을 확인한다

`verify[]`를 실제로 돌린다. 돌리지 않았다면 문서에 **"마지막 확인 시점"**이라고 적는다 — 확인하지 않은 숫자를 현재 상태로 적지 마라.

현재 세션 ID와 트랜스크립트 폴더는 `H current`로 본다. 트랜스크립트 목록은 `ls -t <트랜스크립트 폴더>/*.jsonl`.

### 핸드오프 문서 구조

기존 구조를 유지한다. 없으면 이 골격으로 만든다.

| 절 | 내용 |
|---|---|
| **위험** | 제일 위에. 되돌릴 수 없거나 데이터를 잃는 것 (미커밋, 임시 런타임, 만료 임박) |
| **한 일** | 순서대로. **결정과 결함 중심.** 파일 목록은 나열하지 마라 — git이 한다 |
| **상태** | 측정치와 정본 문서 위치 |
| **환경 복원** | 붙여넣어 실행할 수 있는 명령 |
| **다음 작업** | **막힘 관계를 명시한다** — 무엇이 무엇을 막고 있는지가 우선순위를 정한다 |
| **함정** | **이 문서에서 가장 값어치 있는 절.** 이번 세션이 실제로 밟은 것을 추가한다 |
| **트랜스크립트** | 세션 ID, 실행 폴더, `cd <실행 폴더> && claude --resume <id>` |

### 쓸 때의 규칙

- **주장이 아니라 측정치.** "테스트 통과"가 아니라 "198개 통과, 2026-09-30 확인"
- **"완료"와 "증거 있음"을 구분한다.** 미검증을 숨기지 마라
- **함정 절에 이번 세션이 낭비한 시간을 적는다.** 다음 세션이 같은 함정을 밟지 않는 것이 이 문서의 존재 이유다
- 프로젝트 자체의 문서 규칙이 있으면(예: `CLAUDE.md`) 그것을 따른다

### 레지스트리 엔트리 갱신

1. `H stamp <키>` — `updated`, `last_session_id`, `transcript_dir`를 현재 세션으로 맞춘다. `transcript_dir`가 바뀌었으면(다른 폴더에서 띄운 세션) 보고에 그렇다고 쓴다 — 다음 세션은 그 폴더에서 띄워야 resume된다.
2. `one_line`은 직접 고친다. **다음 세션이 이것만 읽고도 방향을 잡을 수 있게** 쓴다. 환경이나 위험이 바뀌었으면 `setup`/`verify`/`warnings`도.
3. 고친 뒤 `H list`에 이 프로젝트의 ⚠ 점검이 남지 않았는지 본다.

## §3 등록 (`register`)

새 프로젝트를 레지스트리에 추가한다. 필요한 것:

| 필드 | 어떻게 정하나 |
|---|---|
| 키 이름 | 사용자가 부르는 이름. 짧게, 소문자 |
| `aliases` | 다르게 부를 만한 것들 |
| `workdir` | 절대 경로. 저장소 루트인지 확인한다 |
| `handoff_doc` | `workdir` 기준 상대 경로. 관례: `docs/HANDOFF.md` |
| `transcript_dir` | `H current`의 트랜스크립트 폴더 |
| `last_session_id`, `updated` | 저장 뒤 `H stamp <키>` |
| `setup` / `verify` | **추측하지 마라.** 저장소를 읽어 실제 명령을 찾는다(README, Makefile, package.json, scripts/) |
| `warnings` | 미커밋 상태, 임시 런타임, 공유 자원 등 |

`workdir`과 `handoff_doc`이 실제로 존재하는지 확인한 뒤 저장한다. 핸드오프 문서가 없으면 §2의 골격으로 만든다.

---

## §4 목록 (`list`)

1. `H list`를 실행하고 출력을 **코드블록에 그대로** 보여준다. 요약하거나 재배열하지 마라.
2. 밑에 한두 줄만 덧붙인다.
   - ●이 하나면 `/handon <키>`를 제안한다. 여럿이면 그 키들을 나열한다. 없으면 ○ 중 원하는 것의 실행 폴더를 알려준다.
   - ⚠ 점검이 있으면 무엇을 하면 풀리는지. `transcript_dir 불일치`는 그 프로젝트를 이어받은 세션에서 `/handoff <키>`를 하면 `stamp`가 맞춘다. 레지스트리를 지금 직접 고치는 것은 사용자에게 묻고.
