# handoff — 갱신 (push)

`session` 스킬의 **§2 갱신**을 부르는 지름길이다. 아래에서 `H`는 `python3 -I "${CLAUDE_SKILL_DIR}/../../scripts/handoff.py"`다.

1. 인자가 `list`·`ls`·`목록`이면 `/handlist`와 같다 — `H list` 출력을 코드블록으로 보여주고 끝낸다.
2. **대상을 먼저 정한다** — 문서를 고치기 전에.
   - 인자가 있으면 그 프로젝트. 등록되어 있지 않으면(`H resolve <인자> --json`의 `match`가 없으면) 문서를 고치기 전에 이 폴더를 그 이름으로 등록할지 묻는다. 묻지 않고 등록하지 않는다.
   - 인자가 없으면 `H current --json`의 **`push_target`**. 값이 있으면 그 키다(이 세션이 묶인 프로젝트와 실행 폴더의 프로젝트가 같다) — 묻지 않고 첫 줄에 대상을 밝힌다.
   - `push_target`이 `null`이면 **문서를 고치지 않고 묻는다.** `push_target_note`와 `candidates`를 보여 주고, 그중 하나를 고르거나 새 이름을 정해 달라고 한다. 새 이름을 받으면 `session` §3으로 등록한다. `bound`만 보고 쓰지 않는다.
   - 확인하려고 `H pull`을 부르지 않는다. 그 사이 다른 세션이 저장한 것을 충돌로 잡지 못하게 된다.
3. `Skill` 도구로 `baton:session`을 `<키> save` 인자로 호출하고 **§2 갱신**을 그대로 따른다. 요점:
   - 돌고 있는 작업은 멈추지 않고 "실행 중, 결과 미확인"으로 적는다.
   - 문서를 다시 읽고 바뀐 절만 Edit로 고친다. 고정층은 사용자가 이번 세션에 직접 정한 변경만.
   - `H push <키> --json` — 키를 항상 붙인다.
   - `needs_review`면 저장되지 않았다. `fixed_diff`를 그대로 보여 주고 저장할지 묻고 **턴을 끝낸다.** 사용자가 저장하라고 답한 다음 턴에 `H push <키> --review <값> --json`. 같은 턴에 다시 부르지 않는다. 다시 `needs_review`가 나오면 새 diff를 보여 주고 다시 묻는다. 저장하지 말라고 하면 아무것도 하지 않는다 — 문서를 스스로 되돌리지 않는다.
   - `conflict`면 저장되지 않았다. `diff`를 보여 주고 멈춘다. 스스로 합치지 않는다.
   - `partial`이면 같은 명령을 다시.
   - `H set <키> --one-line "…" --json`으로 한 줄 요약.
4. "`C000N` 저장됨"으로 보고한다. 저장됐다는 것은 세션을 닫아도 된다는 뜻이 아니다. 사용자가 세션을 끝낸다고 했을 때만 돌고 있는 작업과 임시 산출물을 정리하고, 그 뒤에 "이 세션을 닫아도 됩니다"와 다음 세션 첫 명령(`cd <실행 폴더> && claude` → `/baton:handon <키>`)을 알려 준다. 사용자가 시키기 전에는 커밋하지 않는다.

사용자와는 한국어로 말한다.
